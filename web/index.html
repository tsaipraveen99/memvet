How it works

MemVet stores a memory as a claim plus the evidence that made it true: the commit, the files, the symbols and their body hashes, and the tests that prove it. On retrieval it re-checks that evidence against the code as it exists now.

Every commit, verdict and reason below comes from one run against a real repository: 29 commits of a working Next.js site, four decisions recorded at the oldest commit.

Why not just watch files

Files change constantly

A tool that flags every touched file flags a typo fix in an unrelated function, then the next one, and the one after that. It gets muted inside a week.

MemVet keys on qualified symbols and hashes their bodies, so it can tell a docstring from a rewrite, and a rename from a deletion.

Install

$ git clone https://github.com/tsaipraveen99/memvet
$ cd memvet
$ python -m pip install -e .
$ memvet init

# record a decision against the code
# that makes it true
$ memvet remember \
    --title "Rate limiting must survive Redis
             being absent" \
    --file lib/ratelimit.ts \
    --symbol checkRate \
    --test lib/ratelimit.test.ts
# what your agent is allowed to rely on
$ memvet context

# re-check every memory against HEAD
# exits non-zero, so it can gate a PR
$ memvet check

# render the findings for review
$ memvet review --base origin/main --json --output web/review.json

Pure standard library in the core path. No model runs in the checking path, so a full pass takes milliseconds. A GitHub Action covers the post-merge surface, and the review viewer turns a report into per-memory verdicts.

What the first real run found

MemVet had 40 passing tests before it was ever pointed at a repository that was not built for it. The first run against real TypeScript broke it in three ways, and all three are worth knowing about if you build something similar.

A regex ate the rest of the file

The brace scanner met a quote inside a regular expression character class, decided a string had opened, and lost count. Symbol bodies ran to the end of the file, so every later edit anywhere in that file looked like a change to the tracked symbol.

FixThe scanner now understands comments, strings, template expressions and regex literals.

Improving the parser invalidated every memory

Changing how a body is sliced changes its hash. Ledgers written by the previous version suddenly reported drift in code nobody had touched, which is precisely the false claim this tool exists to prevent.

FixRecords carry a hash version. Older records have their baseline recomputed from the introduction commit and say so.

Drifted memories were served as silence

Agent context held fresh decisions only. A constraint that had drifted simply vanished, leaving the agent unable to distinguish it from a constraint that never existed.

FixDrifted decisions are exported with a warning and the reason. --only-fresh restores the old behavior.

What it does not do

MemVet is an evidence-based gate, not a correctness proof.

  • It will not tell you a decision is right. It tells you whether the code it rested on still holds.
  • A claim with nothing to anchor to stays needs_revalidation rather than being quietly promoted.
  • Recording a decision is deliberate. It does not guess what mattered in your session.
  • It does not replace your memory layer. It sits on top of one and checks it.
